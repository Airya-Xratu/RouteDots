# RouteDots design briefs

These briefs prepare a consistent redesign of the RouteDots library experience. Start with [design.md](./design.md), then use each brief as a focused design task. Each prompt is self-contained enough to pass to a design agent and references the shared system for visual consistency.

## Briefs

1. [Product overview and marketing page](./01-product-overview.md) — explain the library and lead with the route visualization.
2. [Interactive playground](./02-playground.md) — explore routes and live library customization.
3. [Documentation onboarding](./03-documentation-onboarding.md) — help developers install and render their first route.
4. [API reference](./04-api-reference.md) — make the public API and configuration easy to scan.
5. [Examples gallery](./05-examples-gallery.md) — show practical integration patterns and rendering modes.

Keep the navigation, design tokens, route semantics, and map treatment consistent across all experiences. These are design specifications, not a request to change the library's behavior or claim capabilities it does not have.
